# Domain docs

This is a single-context repository. Read root `CONTEXT.md` before
exploring domain concepts, and read relevant ADRs in `docs/adr/` before
working in their area.

These files are created when useful. If one does not exist yet, continue
without treating its absence as a setup problem. The `/domain-modeling`
skill can create or extend them when terminology or decisions are resolved.

Use the terms defined in `CONTEXT.md` in issues, proposals, tests, and
code discussions. If a term is missing, check whether the project already
uses another name; bring genuine gaps to `/domain-modeling`.

If a proposed change conflicts with an ADR, identify the ADR and explain
why the decision should be revisited.
